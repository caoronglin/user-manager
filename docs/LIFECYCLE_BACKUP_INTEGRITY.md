# 用户生命周期与备份安全边界（2026-10-11）

## 已修正的关键行为

- **账号重命名**：保留原锁定状态；现行 Tab/旧版 CSV 停用记录随用户名迁移。关联配置无法完全迁移时标记失败、账户维持锁定，禁止报告成功。
- **用户识别**：托管账户 = 合法用户名、有效系统账户及受管数据盘下的主目录；配额记录可作为候选来源，但不再是唯一来源。
- **磁盘配额未知**：查询结果缺失/不可读不等于零使用量。Web snapshot `quota` 中使用 `quota_status: "unknown"` 和 `null`，UI 必须按未知显示，不可显示 0/无限额。
- **恢复校验**：校验模块缺失、校验失败、恢复前保护副本失败都不得进入 `rsync --delete`。校验和不存在的历史备份默认拒绝覆盖恢复，须管理员确认后显式设置 `USER_MANAGER_ALLOW_UNVERIFIED_RESTORE=1`。
- **科研数据备份**：`*.bam`、`*.cram`、`*.fastq.gz`、`*.vcf`、`*.gff3` 等数据默认保留；只有明确设置 `USER_MANAGER_BACKUP_EXCLUDE_BIO=1` 才排除。该变量具有丢失备份内容的风险，非临时空间优化建议。

## 验证范围

1. `bash tests/test_lifecycle_failure_contract.sh`
2. `bash tests/test_backup_core.sh`
3. `bash tests/run_regression.sh --level all`
4. 新 CI 分别使用普通 runner 和隔离 Ubuntu 26.04 容器的故障注入测试。
5. 实机验证时只创建专用测试账户与模拟数据；**禁止**在活跃科研账户上执行破坏性恢复或全量删除。

## 尚未承诺

- CLI/TUI 用户创建-更新-改名全流程仍没有真正的跨模块原子事务，失败时可以出现“部分迁移、保持锁定、需人工处理”。
- 校验和是生成时内容一致性证明，不能替代异地离线备份或加密签名。
- CI 不能证明生产挂载/系统 PAM、QuotaFS、SMB、DNS、Cron 在目标服务器上全部正常。
- 历史备份可能由于此前默认排除科研文件而不完整：更改新版本排除策略**不会修复旧备份**。需要重新备份并核验重要样本数据。
